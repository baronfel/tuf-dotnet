# TUF Cross-Language Interoperability

The .NET TUF implementation is designed to be fully interoperable with other TUF implementations across different programming languages and ecosystems. This guide explains how to ensure compatibility and what has been tested.

## Overview

The Update Framework (TUF) specification defines a standard protocol for secure software updates. Multiple implementations exist across different languages:

- **Python-TUF**: The reference implementation in Python
- **Go-TUF**: Production-ready implementation in Go
- **JavaScript-TUF**: Implementation for JavaScript/Node.js environments  
- **Rust-TUF**: Implementation in Rust (various projects)
- **.NET TUF**: This implementation in C#/.NET

Interoperability between these implementations is crucial for:
- **Mixed environments**: Using different implementations across client/server
- **Migration**: Moving from one implementation to another
- **Compatibility**: Ensuring repositories work with all compliant clients

## Verified Interoperability

### ✅ Python-TUF Compatibility

The .NET implementation has been verified to be compatible with Python-TUF:

- **Can read**: Metadata generated by Python-TUF
- **Can be read by**: Python-TUF can read metadata generated by .NET
- **Signature verification**: Works across both implementations
- **Conformance**: Both pass the official TUF conformance test suite

**Example**: Reading Python-generated root metadata
```csharp
using CanonicalJson;
using TUF.Models;

// Python-generated TUF metadata can be parsed directly
var pythonMetadata = File.ReadAllText("python-generated-root.json");
var root = CanonicalJson.Serializer.Deserialize<Metadata<Root>, MetadataProxy.De<Root>>(pythonMetadata);

// Signature verification works the same way
var isValid = root.VerifySignatures(trustedKeys);
```

### ✅ Go-TUF Compatibility  

The .NET implementation has been verified to be compatible with Go-TUF:

- **Can read**: Metadata generated by Go-TUF
- **Can be read by**: Go-TUF can read metadata generated by .NET
- **Target files**: Compatible handling of target file metadata
- **Delegations**: Compatible delegation handling

**Example**: Reading Go-generated targets metadata
```csharp
// Go-generated targets metadata works seamlessly
var goMetadata = File.ReadAllText("go-generated-targets.json");  
var targets = CanonicalJson.Serializer.Deserialize<Metadata<Targets>, MetadataProxy.De<Targets>>(goMetadata);

// Access target files as usual
foreach (var (path, targetFile) in targets.Signed.TargetMap)
{
    Console.WriteLine($"Target: {path}, Length: {targetFile.Length}");
    foreach (var (algorithm, hash) in targetFile.Hashes)
    {
        Console.WriteLine($"  {algorithm}: {hash}");
    }
}
```

## Key Compatibility Features

### Canonical JSON Serialization

All TUF implementations must produce identical canonical JSON for signature verification:

```csharp
// Our canonical JSON matches other implementations
var key = new Key { KeyType = "ed25519", Scheme = "ed25519", /* ... */ };
var json = CanonicalJson.Serializer.Serialize(key);

// Properties are in lexicographic order: keytype, keyval, scheme
// No extra whitespace, consistent formatting
```

**Verified**: Our canonical JSON output is compatible with Python-TUF and Go-TUF.

### Key ID Calculation

Key IDs must be calculated identically across implementations:

```csharp
// Key ID calculation matches other implementations exactly
var keyId = key.GetKeyId(); // SHA-256 hash of canonical JSON

// This matches Python-TUF and Go-TUF calculations
Assert.Equal("9c77c0b277eab2fb88d41546d25c82a57286e86969bee8187dedc195e900fb8f", keyId);
```

**Verified**: Key ID calculation produces identical results to Python-TUF and Go-TUF.

### Signature Verification

Cryptographic signature verification works across implementations:

- **Ed25519**: Compatible with all implementations
- **ECDSA P-256**: Compatible with Python-TUF and Go-TUF  
- **RSA-PSS**: Compatible with Python-TUF and Go-TUF

```csharp
// Signatures created by Python-TUF can be verified by .NET
var isValid = key.VerifySignature(pythonGeneratedSignature, signedData);
```

## Testing Interoperability

### Automated Testing

The repository includes automated interoperability tests:

```bash
# Run cross-language interoperability tests
dotnet test TUF.InteroperabilityTests/ --configuration Release

# Run official TUF conformance tests
# (requires TUF conformance test suite)
./run-conformance-tests.sh
```

### Manual Testing

To test interoperability manually:

1. **Generate metadata** with another implementation
2. **Parse with .NET** using the TUF library
3. **Verify signatures** work correctly
4. **Test round-trip** by generating metadata with .NET and parsing with the other implementation

**Example workflow**:
```bash
# Generate metadata with Python-TUF
python3 generate_metadata.py --output python-metadata/

# Test with .NET TUF CLI  
dotnet run --project examples/TufConformanceCli -- init python-metadata/root.json --metadata-dir ./test-metadata

# Verify metadata refresh works
dotnet run --project examples/TufConformanceCli -- refresh --metadata-dir ./test-metadata --metadata-url http://localhost:8000/metadata
```

## Common Compatibility Issues

### JSON Formatting Differences

**Issue**: Different JSON formatting can break signature verification.

**Solution**: Always use canonical JSON for signed metadata:
```csharp
// ✅ Correct: Use canonical JSON
var signedBytes = CanonicalJson.Serializer.Serialize(metadata.Signed);

// ❌ Incorrect: Regular JSON may have different formatting  
var wrongBytes = JsonSerializer.SerializeToUtf8Bytes(metadata.Signed);
```

### Date Format Variations

**Issue**: Different date/time formatting can cause parsing errors.

**Solution**: Use ISO 8601 format consistently:
```csharp
// ✅ Correct: ISO 8601 with Z suffix
var expires = DateTimeOffset.Parse("2025-12-31T23:59:59Z");

// ❌ Incorrect: Other formats may not be compatible
var wrong = DateTime.Now.ToString(); // Platform-specific formatting
```

### Key Format Differences

**Issue**: Different key encodings or formats.

**Solution**: Use standard TUF key formats:
```csharp
// ✅ Correct: Standard PEM format for ECDSA/RSA
KeyVal = new KeyValue { 
    Public = "-----BEGIN PUBLIC KEY-----\nMFkw...\n-----END PUBLIC KEY-----\n" 
};

// ✅ Correct: Hex encoding for Ed25519  
KeyVal = new KeyValue {
    Public = "abcdef1234567890abcdef1234567890abcdef1234567890abcdef1234567890"
};
```

## Migration Guide

### From Python-TUF

1. **Export metadata** from Python-TUF repository
2. **Verify compatibility** with .NET TUF client
3. **Update tooling** to use .NET TUF CLI
4. **Test thoroughly** in staging environment

### From Go-TUF

1. **Export repository state** including all metadata
2. **Verify target file handling** works correctly
3. **Test delegation workflows** if used
4. **Validate signature verification** across all metadata

### To Other Implementations

1. **Generate test metadata** with .NET implementation
2. **Verify parsing** works with target implementation
3. **Test signature verification** in both directions
4. **Validate conformance** using official test suite

## Conformance Testing

The .NET TUF implementation participates in the [official TUF conformance test suite](https://github.com/theupdateframework/tuf-conformance):

```yaml
# GitHub Actions workflow excerpt
- name: Run TUF Conformance Tests
  uses: theupdateframework/tuf-conformance@v2
  with:
    entrypoint: ./tuf-conformance-cli/TufConformanceCli
    xfail-file: .tuf-conformance-xfails
```

**Benefits of conformance testing**:
- Validates specification compliance
- Ensures interoperability with other implementations
- Catches compatibility regressions
- Provides confidence for production use
